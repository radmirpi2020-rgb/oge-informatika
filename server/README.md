# server — контент сайта в PostgreSQL, админка на Payload

Здесь живёт **база контента** сайта «Информатика 5–9 класс / Подготовка к ОГЭ»:
Payload CMS 3 + PostgreSQL. Сайт (корень репозитория) остаётся статическим и умеет
работать как от базы (REST), так и от файлов `data/*.js` — на выбор.

| Что | Где |
|---|---|
| Коллекции: курсы, модули, уроки (задачи, практики, поля ОГЭ), медиа | `src/collections/*` |
| Тарифы и лимиты нейронки | `src/globals/Plans.ts` |
| Конфиг Payload (Postgres-адаптер, CORS, язык админки) | `src/payload.config.ts` |
| Импорт контента сайта в базу | `src/seed/import-site.ts` |
| Проверка целостности базы | `src/seed/verify.ts` |
| Первый пользователь админки | `src/seed/create-admin.ts` |
| Публикация импортированного (снятие черновика) | `src/seed/publish.ts` |
| Портативный PostgreSQL для разработки | `scripts/dev-db.mjs`, `scripts/db-check.mjs` |

## Быстрый старт

```bash
cd server
pnpm install
cp .env.example .env        # уже создан при настройке; проверь DATABASE_URL и PAYLOAD_SECRET
pnpm db:start               # поднимает портативный Postgres на 127.0.0.1:5433 и базу oge_site (UTF8)
pnpm seed                   # импорт: 2 курса, 32 модуля, 400 уроков, задачи и практики
pnpm publish:content        # импортированное становится опубликованным, а не черновиком
pnpm admin:create           # первый пользователь админки: admin@local.test / oge-admin-2026
pnpm dev                    # http://localhost:3000/admin — админка
pnpm verify                 # проверка: 300+100 уроков, 21 балл, 32 живых прогона, короткий трек
```

Полезное:

```bash
pnpm db:status              # работает ли база
pnpm db:check               # кодировка UTF8 и русский текст без искажений
pnpm db:stop                # остановить базу
pnpm generate:types         # пересобрать src/payload-types.ts после правки конфига
pnpm export:static          # выгрузить контент из базы в файлы сайта (см. ниже)
```

## Как сайт берёт контент

Два режима, переключается одним файлом `config/api.js` в корне проекта:

| Режим | Как включить | Что происходит |
|---|---|---|
| **Файлы** (по умолчанию) | `window.SITE_API = ""` | сайт работает без сервера и интернета, уроки из `data/lessons-bundle.js` и `data/oge/oge-lessons.js` |
| **База** | `window.SITE_API = "http://127.0.0.1:3000"` | `scripts/core/api.js` загружает курсы, модули и уроки из Payload и пересобирает реестр уроков; если сервер недоступен — сайт молча остаётся на файлах |

Номера уроков (`siteId`: 1–300 школьный курс, 1001–1100 курс ОГЭ) в базе и в файлах совпадают,
поэтому прогресс ученика в localStorage не теряется при переключении режима.

**Снимок для офлайна.** База — источник истины, но сайт должен открываться и без сервера,
поэтому есть экспорт в файлы:

```bash
node tools/export-from-payload.js            # из корня проекта, сервер должен быть поднят
# → data/lessons-bundle.js (300 уроков, 13 модулей)
# → data/oge/oge-lessons-bundle.js (100 уроков, 19 модулей)
node tools/smoke-test.js && node tools/render-test.js
```

Обратно (файлы → база): `pnpm seed` (идемпотентно: обновляет по `siteId`, не плодит копии).

## Схема данных

```
courses (base | oge)
  └── modules (задание ОГЭ, балл, часы, цель, критерий закрытия,
  │            файлы модуля, минимум живых прогонов, «чего симуляция не проверит»)
        └── lessons (siteId, тип, минуты, теория, задачи[], практика{engine, config},
                     группа «Курс ОГЭ»: задание, режим, файлы к уроку, короткий трек)
users   — вход в админку
media   — картинки и озвучка сайта
plans   — глобальный: тарифы, лимиты токенов, промокоды
```

Особенности, о которых стоит знать:

- `siteId` менять нельзя — это ключ прогресса ученика в браузере.
- У `lessons` и `modules` включены **черновики** (`versions.drafts`): можно готовить правку
  и публиковать её отдельно. Урок, сохранённый черновиком, на сайт не попадёт.
- Поле готовности называется `contentStatus` (каркас → черновик → готов), чтобы не путаться
  с системным `_status` черновика Payload.
- Тексты уроков хранятся как есть, в «сайтовой» разметке (`**жирный**`, `> Лайфхак.`,
  `!! Ошибка.`, блок `~~~`), потому что её рендерит `App.md` на сайте.

## Локальный PostgreSQL: почему так

PostgreSQL в системе не установлен и Docker недоступен, поэтому база поднимается пакетом
`embedded-postgres` (портативные бинарники, без прав администратора). Две ловушки Windows,
из-за которых `scripts/dev-db.mjs` написан именно так:

1. **Каталог данных не должен лежать в пути с кириллицей.** `initdb` передаёт путь
   в ANSI-кодировке, и Postgres с UTF8 падает: `invalid byte sequence for encoding "UTF8"`.
   Поэтому данные по умолчанию в `%USERPROFILE%\.oge-pgdata` (можно задать `PG_DATA_DIR`).
2. **На русской локали нельзя просить `initdb --encoding=UTF8`** — падает post-bootstrap.
   Кластер инициализируется штатно, а рабочая база `oge_site` создаётся отдельно
   из `template0` с `ENCODING 'UTF8'` (это делает `dev-db.mjs`).

## Аккаунты учеников: регистрация, подтверждение почты, сброс пароля

Коллекция `students` — это аккаунты сайта (не путать с `users`: там вход в админку).
Поверх неё на сайте работает страница `#/account` (`scripts/pages/account.js`).

| Что | Эндпоинт | Кто может |
|---|---|---|
| Регистрация | `POST /api/students` | кто угодно |
| Вход | `POST /api/students/login` | кто угодно |
| Выход | `POST /api/students/logout` | вошедший |
| Кто я | `GET /api/students/me` | вошедший |
| Подтвердить почту | `POST /api/students/verify/:token` | по ссылке из письма |
| Забыл пароль | `POST /api/students/forgot-password` | кто угодно |
| Новый пароль | `POST /api/students/reset-password` | по ссылке из письма |
| Прогресс | `GET/POST/PATCH /api/progress` | только свой документ |

Что важно знать про доступ:

- **Вход без подтверждения почты закрыт** — так настроено в `Students.auth.verify`. Сначала письмо, потом вход.
- **Прогресс изолирован**: `read` возвращает только документ, где `student` равен текущему пользователю.
  Аноним получает «нет права» — это проверено тестом.
- **Регистрация не даёт прав администратора**: поля кроме `email`, `password`, `name`, `grade`,
  `course`, `consent` закрыты для самостоятельной записи (поле-уровневый доступ в `Students.ts`).
  Попытка прислать себе `roles: ["admin"]` игнорируется.

Проверка всего этого цикла — одной командой (сервер поднимать не нужно, работает Local API):

```bash
cd server && pnpm auth:test
```

Ожидаемый вывод — 16 проверок «ок», включая запрет входа без подтверждения и невидимость чужого прогресса.

### Почта

Письма нужны для двух вещей: подтверждение почты и сброс пароля. Пока SMTP не настроен,
Payload **пишет письма в консоль сервера** — этого достаточно, чтобы пройти регистрацию
и сброс пароля при разработке: запусти `pnpm dev`, зарегистрируйся на сайте, скопируй
ссылку из консоли и открой её.

Чтобы письма уходили по-настоящему, заполни в `server/.env`:

```bash
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=почта@твойдомен.ru
SMTP_PASS=пароль-приложения        # не обычный пароль от почты!
MAIL_FROM=почта@твойдомен.ru
MAIL_FROM_NAME=Информатика и ОГЭ
SITE_URL=http://127.0.0.1:8080     # адрес сайта: из него собираются ссылки в письмах
```

Настройки популярных провайдеров:

| Провайдер | Хост | Порт | Пароль |
|---|---|---|---|
| Яндекс.Почта (для домена) | `smtp.yandex.ru` | 465, SSL | пароль приложения (включить «Пароли приложений» в Яндексе) |
| Mail.ru | `smtp.mail.ru` | 465, SSL | пароль для внешнего приложения |
| Gmail | `smtp.gmail.com` | 587, STARTTLS (`SMTP_SECURE=false`) | пароль приложения (нужна двухфакторная аутентификация) |
| Свой домен / Resend / Unisender | по инструкции провайдера | 465 или 587 | API-ключ или пароль SMTP |

Ловушки, о которых лучше знать заранее:

1. **Обычный пароль от почты не сработает** — нужен пароль приложения (Яндекс, Gmail, Mail.ru
   требуют его, если включена двухфакторная аутентификация).
2. **Письма улетают в «спам»** — пока у домена нет SPF и DKIM. Для школьного проекта
   достаточно честной подписи и текста без ссылок-сокращателей; для продакшена — настроить
   домен у провайдера рассылок.
3. **Ссылка в письме ведёт на `SITE_URL`.** Если сайт открыт по другому адресу (другой порт,
   ngrok-ссылка), поменяй `SITE_URL` в `.env` — иначе ссылка приведёт «в никуда».
4. **Яндекс ограничивает рассылку** (порядка сотен писем в сутки на ящик). Для класса хватает,
   для школы — бери провайдера рассылок.

Ссылки в письмах ведут на сайт: `#/account?verify=<токен>` и `#/account?reset=<токен>`.
Эти адреса разбирает роутер (`App.router.query()`) и страница аккаунта.

### Как это включается на сайте

1. Поднять сервер: `cd server && pnpm db:start && pnpm dev`.
2. В корне проекта в `config/api.js` указать `window.SITE_API = "http://127.0.0.1:3000";`.
3. Открыть сайт и зайти на `#/account`.

Без шага 2 страница аккаунта честно скажет, что сервер не настроен, — сайт при этом
продолжает работать на файлах, ничего не ломается.

Прогресс ученика пока считается в браузере (localStorage) и по кнопке сохраняется
в аккаунт (коллекция `progress`) либо загружается обратно на другом устройстве.
Автоматическая синхронизация при каждом ответе не сделана намеренно: сайт должен
работать офлайн, без сервера.

## Продакшен

- **Настоящий Postgres**: поднимите сервер (или контейнер `postgres:18`) и укажите
  `DATABASE_URL=postgres://user:pass@host:5432/oge_site`. Каталог данных — обычный.
- **Миграции вместо автосхемы**: `PAYLOAD_DISABLE_PUSH=1` в `.env`, затем
  `pnpm payload migrate:create` и `pnpm payload migrate` на деплое.
- **Секрет**: `PAYLOAD_SECRET` — длинная случайная строка, не из примера.
- **CORS**: `SITE_ORIGIN` — адрес, где открыт статический сайт; он же попадает в `cors`/`csrf`.
- **Сборка**: `pnpm build && pnpm start` (Next.js 16 + Payload 3, Node ≥ 20.9).

## Провожатый: ключ DeepSeek только на сервере

Ключ, который лежит в браузере, может увести любой человек через F12 — на публичном сайте
это чужие деньги. Поэтому ключ переносится на сервер, а сайт обращается к прокси `/api/ai`.

**Как включить:** добавить в `server/.env` строку `DEEPSEEK_API_KEY=sk-...` и указать адрес
сервера в `config/api.js` сайта. Больше ничего: сайт сам начинает ходить через прокси
(в `scripts/ai/ai.js` это `App.ai.viaProxy()`), а ключ из браузера можно убрать.

Что проверяет прокси на каждый запрос (файл `src/app/api/ai/route.ts`):

| Проверка | Зачем |
|---|---|
| Ученик вошёл (JWT коллекции `students`) | анонимный посетитель не тратит твои деньги |
| Дневной лимит ученика из `progress.aiUsage` | нельзя выжечь весь баланс за вечер |
| Длина запроса не больше `AI_MAX_PROMPT` | защита от «перескажи весь учебник» |
| Ключ подставляется только на сервере | в браузер он не попадает вообще |

Расход считается по потоку ответа: сервер разбирает `data:` строки от DeepSeek, берёт
`usage` и дописывает его в `progress.aiUsage` за сегодня. Учёт не ломает ответ — если
запись не удалась, ученик всё равно получит текст.

```bash
# проверка, что прокси настроен и видит ключ
curl http://127.0.0.1:3000/api/ai
# → { "endpoint": "/api/ai", "keyOnServer": true, "dailyTokens": 250000, ... }

# запрос от имени ученика (нужен JWT из /api/students/login)
curl -X POST http://127.0.0.1:3000/api/ai \
  -H "Content-Type: application/json" -H "Authorization: JWT <токен>" \
  -d '{"messages":[{"role":"user","content":"Объясни коротко, что такое бит"}]}'
```

Настройки в `.env`: `DEEPSEEK_API_KEY`, `DEEPSEEK_MODEL` (по умолчанию `deepseek-chat`),
`AI_DAILY_TOKENS` (по умолчанию 100 000 — как в тарифе «Максимум» из `data/plans.js`),
`AI_MAX_PROMPT` (по умолчанию 12 000 символов).

Важно про тарифы: сейчас **бесплатный** и **«Полный курс»** нейронку не включают
(поле `ai: false` в `data/plans.js`), провожатый входит только в «Максимум».
Ключ на сервере один на всех, поэтому тариф без нейронки защищён на клиенте —
если понадобится жёсткая проверка, прокси должен читать тариф ученика из базы
(коллекция `students`, поле `course`, или отдельное поле плана) и отказывать в ответе.

Порядок действий, когда ключ уже вставлен в браузер и сайт опубликован:

1. добавить `DEEPSEEK_API_KEY` в `.env` сервера;
2. в `config/api.js` указать `window.SITE_API = "http://адрес-сервера"`;
3. удалить `config/deepseek-key.local.js` — он больше не нужен;
4. **отозвать старый ключ** в кабинете DeepSeek и создать новый, раз старый полежал в браузере.

## Чего здесь нет

- **Автоматической синхронизации прогресса.** Прогресс считается в браузере, а в аккаунт
  сохраняется кнопкой (или загружается обратно на другом устройстве). Так сайт продолжает
  работать офлайн и без сервера — это осознанный выбор, а не недоделка.
- Оплаты: тарифы и промокоды лежат в базе как справочник, платежей нет.
- Оценки ответов: проверка задач остаётся на клиенте (по той же причине — офлайн).
- Медиа: коллекция создана, файлы пока не залиты (картинки и озвучка лежат в `assets/`).
