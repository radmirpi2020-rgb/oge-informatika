# Шаблон ОГЭ-курса: 100 уроков, режимы «симуляция / скачать / реальный инструмент»

Это **шаблон**: сначала правила и поля, потом генерация. Сам курс генерируется из шаблона
скриптом `tools/build-oge-course.js` — руками уроки не пишутся, руками правится только шаблон
и реестр.

| Что | Где | Роль |
|---|---|---|
| Шаблон (этот файл) | `docs/OGE-COURSE-TEMPLATE.md` | правила: поля, режимы, пороги, минимумы |
| Реестр курса | `data/oge/oge-course.js` → `og.MODULES` | модули, цели, уроки, связи с базовым курсом |
| Политика доставки | `data/oge/oge-delivery.js` → `og.DELIVERY` | что скачать, что симулировать, сколько раз делать вживую |
| Генератор | `tools/build-oge-course.js` | собирает курс и проверяет сходимость |
| **Готовый курс** | `docs/OGE-COURSE-CONTENT.md` | сгенерированный план: 100 уроков с режимами |
| Машиночитаемый план | `data/oge/course-plan.js`, `data/oge/delivery-manifest.json` | для сайта и админки |
| Каркасы модулей | `data/oge/module-NN-*.js` | генерирует `tools/build-oge-modules.js` |

## 1. Главное правило доставки

> **Тяжёлое — скачать и работать в настоящей программе. Лёгкое — симулировать внутри сайта.
> Но каждое практическое задание несколько раз обязательно делается на реальном инструменте.**

Почему так, а не «всё в браузере»:

- Задания 13, 14, 15, 16 оценивают **файл в конкретном формате** (`.odp`, `.odt`, `.ods`, программа)
  и **работу в конкретной среде** (Impress, Calc, Кумир, Python). Браузерная имитация не тренирует
  ни формат, ни меню, ни ошибки сохранения — а именно на них теряют баллы (в региональном анализе
  ОГЭ-2025 работы, сохранённые не в тот формат, оценивались в 0).
- Задания 1–12 — это чистые данные и алгоритмы: их вес и ценность для тренировки не зависят
  от установленного софта. Их место — симуляция с автопроверкой.

### Порог: что считается «тяжёлым»

| Признак | Решение | Почему |
|---|---|---|
| Данных ≤ 5 МБ, навык не зависит от интерфейса программы | `sim` — симуляция внутри сайта | скачивать нечего, проверка автоматическая |
| Установщик > 30 МБ (LibreOffice, Python, Кумир) | `download` + `real` | без установки навык не формируется |
| Данных > 5 МБ (архив ФИПИ 113,7 МБ) | `download`, но **не архивом** — только нужный файл | правило «минимальная часть» из §4 |
| Формат ответа `.odp` / `.odt` / `.ods` / `.txt` | `real` обязательно | формат — часть критерия |
| Нужна файловая система (задания 11, 12) | `real` обязательно | поиск по содержимому и маска — средствами ОС |

### Режимы урока (`mode`)

| Код | Что значит для ученика | Что показывает сайт |
|---|---|---|
| `sim` | ничего скачивать не надо | интерактив + автопроверка (движки `sandbox`, `code`, `graph`, `table`, `robot`) |
| `download` | скачать файл данных (или инструмент) до урока | карточка «скачать»: имя, размер, ссылка, зачем |
| `real` | обязательно проделать в настоящей программе и приложить результат | инструкция, чек-лист самопроверки, счётчик прогонов |
| `exam` | полная симуляция на 150 минут | таймер, вариант, оценка по критериям |

Режим — это **минимум требований**, а не «или-или»: урок с `real` обычно ещё имеет `sim`-разминку.

## 2. Схема урока (контракт для генератора)

Урок в реестре может быть строкой (как сейчас) или объектом:

```js
{
  t: "Круговая диаграмма: данные, легенда, подписи значений",  // заголовок
  kind: "practice",        // lesson | practice | exam
  mode: "real",            // sim | download | real | exam  (вычисляется генератором)
  download: ["lo"],        // ключи из og.DELIVERY.assets
  sim: "table",            // движок, если у урока есть симуляция
  real: 1,                 // сколько раз сделать вживую ИМЕННО на этом уроке
  min: 15                  // минуты
}
```

Строка допустима и превращается в объект автоматически — режим считается по ключевым словам (§3).
Обязательные поля урока: заголовок и режим. Всё остальное — с дефолтами.

### Схема модуля (уже есть в `oge-course.js`)

```js
{
  id: "d15", exam: "14", n: "14", order: 16,
  title: "Электронная таблица: обработка данных",
  ball: 3, hours: 10,
  goal: "…",                        // что ученик умеет после модуля
  lessons: [ /* 10 уроков */ ],
  base: [121, 133],                 // уроки базового курса, закрывающие тему
  gap: ["…"],                       // чего в базовом курсе нет
  engine: "table",                  // основной движок симуляции
  check: "…"                        // критерий «модуль закрыт»
}
```

## 3. Как генератор назначает режимы (детерминированные правила)

Правила применяются по порядку, первое совпадение выигрывает:

| № | Условие в заголовке урока | Режим |
|---|---|---|
| 1 | `симуляц`, `Проходим демоверсию`, `генеральная репетиция` | `exam` |
| 2 | `LibreOffice`, `Impress`, `Writer`, `Calc`, `Кумир`, `Робот`, `Python`, `.odp`, `.odt`, `.ods`, `Сдача: имя файла` | `real` |
| 3 | `файловом менеджере`, `маска`, `дереву каталогов`, `расширение файла`, `по содержимому` | `real` |
| 4 | `скачать`, `архив`, `набор данных`, `картинк`, `шаблон` | `download` |
| 5 | всё остальное | `sim` |

Правило 2 намеренно жадное: любой урок, где названа настоящая программа, — это урок в реальной
программе. Лучше перевыполнить требование, чем потерять балл на формате.

### Ручные исключения (`og.DELIVERY.modeOverrides`)

Правила по ключевым словам иногда обманывают, поэтому для двух модулей есть явные исключения:

```js
modeOverrides: {
  d17: { default: "sim", 1: "real", 2: "real", 6: "real", 7: "real" }, // Python: каркас, ввод, тесты, границы
  d15: { 5: "real", 7: "real", 9: "real" }                             // Calc: условные вычисления, диаграмма, тайминг
}
```

`default` применяется к урокам модуля, у которых нет своего номера в списке. Ключ — `id` модуля,
значение — номер урока из реестра.

### Про режим `download`

В текущем наполнении отдельный режим `download` может не назначаться ни одному уроку: загрузки
привязаны к **модулю** (`og.DELIVERY.assetsFor`) и показываются в каждом уроке, где ученик работает
вживую. В сгенерированном плане это видно колонкой «Файлы к уроку» — так требование «пусть скачают
таблицу» не теряется. Режим `download` остаётся в шаблоне для уроков, которые целиком про получение
файла (например, «скачай архив и распакуй его»).

## 4. Что скачать (и что сознательно не качать)

Полные данные с размерами и ссылками — в `data/oge/delivery-manifest.json` (генерируется).
Правила:

1. **Архив ФИПИ (113,7 МБ) не качаем целиком.** Извлекаем только нужное: `task14.ods` (задание 14),
   файлы `DEMO-13/*.odt` (задание 13), `DEMO-12` (задания 11–12). Каждый файл — единицы мегабайт.
2. **Инструменты ставим один раз:** LibreOffice (Writer, Calc, Impress) и Кумир. Python — по желанию,
   но для задания 16 лучше поставить: онлайн-компиляторы на экзамене недоступны.
3. **Учебные данные генерируем, а не качаем:** дерево файлов для заданий 11–12 и «большая таблица»
   для задания 14 собираются скриптом локально (~1–2 МБ). Это быстрее и безопаснее чужого архива.
4. **Онлайн-замены годимся только для черновика:** `qumir.dev` (Кумир в браузере) — чтобы
   попробовать алгоритм, но синтаксис `нц пока … кц` и поведение Робота добиваются в настоящем Кумире.

## 5. Сколько раз делать вживую («несколько раз» — это число)

Минимумы закреплены в `og.DELIVERY.realMinimum` и проверяются генератором:

| Модуль | Задание | Минимум живых прогонов | Что именно |
|---|---|---|---|
| d11 | 11 | 2 | поиск по содержимому в файловом менеджере + в текстовом редакторе |
| d12 | 12 | 2 | маска `*.htm` / `*?.htm` в файловом менеджере + проверка суммарного объёма |
| d13 | 13.1 | 3 презентации | из них 1 на время 25 минут, 1 «с нуля» без подсказок |
| d14 | 13.2 | 3 документа | из них 1 на время 25 минут |
| d15 | 14 | 4 решения | 2 на большом массиве (сотни строк), 1 на время 30 минут |
| d16 | 15 | 10 лабиринтов | из них 2 на время 25 минут, минимум 3 разных набора стен |
| d17 | 16 | 3 программы | запуск локальным Python, проверка на тестах из условия |
| d18 | 13–16 | 4 полных варианта | из них ≥ 2 целиком на реальных инструментах |
| d0 | все | 1 | демоверсия на 150 минут в реальных условиях |

Итого: **не меньше 32 живых прогонов**, из них 5 — на время.

## 6. Раскладка 100 уроков

| № | Модуль | Задание | Балл | Часы | Уроков | Из них живых |
|---|---|---|---|---|---|---|
| 1 | d0 диагностика | весь вариант | 21 | 3 | 4 | 1 полный вариант |
| 2–13 | d1…d12 | 1–12 | 12 × 1 | 3–5 | **51** | 4 (модули d11, d12) |
| 14 | d13 презентация | 13.1 | 2 | 5 | 7 | 3 |
| 15 | d14 текстовый документ | 13.2 | 2 | 6 | 7 | 3 |
| 16 | d15 электронная таблица | 14 | 3 | 10 | 9 | 4 |
| 17 | d16 Робот | 15 | 2 | 8 | 8 | 10 |
| 18 | d17 Python | 16 | 2 | 9 | 8 | 3 |
| 19 | d18 симуляции | 13–16 | 21 | 8 | 6 | 4 полных варианта |
| | **Итого** | | **21** | **99** | **100** | **32** |

Часть 1 — 55 уроков (55 %), часть 2 — 45 уроков (45 %), хотя часть 2 стоит 9 баллов из 21.
Так специально: часть 1 даёт дешёвые баллы и её нужно довести до автоматизма, а часть 2 —
дорогая, но её закрывают 45 уроков, в каждом практическом модуле с обязательными живыми прогонами.

Состав уроков по режимам (проверено генератором): **76 симуляций, 19 уроков «вживую»,
5 полных вариантов на 150 минут.** Отдельный режим `download` в текущем наполнении не назначен
ни одному уроку — загрузки привязаны к модулю и видны в колонке «Файлы к уроку» (см. §3).

### Два трека из одного шаблона: 100 и 85 уроков

Решение по объёму: **полный курс — 100 уроков** (основной трек, старт в сентябре),
**короткий трек — 85 уроков** (старт в марте, 8 недель). Оба собираются одним генератором
из одних данных, различаются только списком уроков.

Что режется в коротком треке: **только глубина части 1** (кодировки КОИ-8 и UTF-16, таблицы
истинности, законы де Моргана, Дейкстра и перебор путей, порядок обхода графа, сортировка в таблице).
Практические модули 13–17 и симуляции d18 проходятся целиком.

Что **нельзя** резать (проверяется генератором): уроки «вживую», полные варианты на 150 минут
и последний урок каждого практического модуля (сдача и самопроверка). Поэтому живых прогонов
в коротком треке столько же — **32**.

Почему не 70 и не 60 уроков: при дальнейшем сокращении выпадают уроки экзаменационных типов задач
(«наименьшее x» в задании 3, «подбор A» в задании 6, «формула включений-исключений» в задании 8,
«сложение в двоичной» в задании 10) — это уже не короткий трек, а другой, худший экзамен.
Если сроки совсем поджимают, честнее идти по короткому треку без симуляций-«повторов»,
чем выкидывать типы задач.

## 7. Что проверяет генератор (падает, если не сходится)

```
node tools/build-oge-course.js
```

1. Уроков ровно **100**; сумма баллов по плану КИМ ровно **21**.
2. У каждого урока посчитан `mode`, и нет уроков без режима.
3. Каждый модуль части 2 (d13–d17) содержит ≥ 1 урок `real` и ≥ 1 урок `sim`.
4. Счётчик живых прогонов по каждому модулю ≥ минимума из `og.DELIVERY.realMinimum`.
5. Все ключи `download` существуют в `og.DELIVERY.assets` (иначе — опечатка в реестре).
6. Каждое задание 1–16 (и оба варианта 13.1/13.2) закрыто хотя бы одним модулем.
7. Короткий трек укладывается в `maxLessons` (**85 из 100** на сейчас).
8. В коротком треке **столько же живых прогонов** (32), и он не потерял ни одного урока «вживую»
   и ни одного полного варианта — это проверяется сравнением счётчиков режимов.
9. Последний урок каждого практического модуля (сдача, самопроверка, тайминг) есть в коротком треке.
10. У каждого модуля в коротком треке ≥ 2 урока, ни один модуль с обязательными живыми
    прогонами не выпал.

## 8. Критерии приёмки урока (когда каркас становится готовым уроком)

| Поле | Требование |
|---|---|
| `theory` | 1–2 экрана, разметка из `docs/CONTRACT.md`, есть строка `> **Лайфхак.**` и `!! **Ошибка.**` |
| `tasks` | ≥ 5 задач: минимум 3 `input`, 1 `choice`, у каждой — `explain` |
| `sim` | если режим `sim` или `exam`: движок реализован и задача решается до конца без «заглушек» |
| `download` | карточка загрузки: имя файла, размер, ссылка, что с ним делать |
| `real` | пошаговая инструкция + чек-лист самопроверки + поле «сколько раз сделал» |
| Проверка | `node tools/check-content.js` и `node tools/test-practices.js` проходят |

Модуль считается закрытым, когда все его уроки прошли приёмку и выполнены живые прогоны из §5.
