# Второй курс: «Подготовка к ОГЭ» — исходники и как их наполнять

Курс «Информатика 5–9 класс» (300 уроков) — это **первый** курс: школьная программа.
Второй курс — **подготовка к ОГЭ**, и он строится не с нуля, а как надстройка: темы уже есть,
не хватает экзаменационного формата, критериев и тренажёров.

- План подготовки для человека (что учить и в каком порядке): `docs/OGE-2026-PLAN.md`
- **Шаблон курса: 100 уроков, режимы «симуляция / скачать / вживую»**: `docs/OGE-COURSE-TEMPLATE.md`
- **Готовый курс (сгенерирован)**: `docs/OGE-COURSE-CONTENT.md`
- Политика доставки (что скачать, сколько раз делать вживую): `data/oge/oge-delivery.js`
- Генератор курса: `node tools/build-oge-course.js`
- Каркас данных: `data/oge/oge-course.js`
- Каркасы модулей: `data/oge/module-*.js` (генерируются)
- Манифест с проверенными цифрами: `data/oge/MANIFEST.json`
- Машиночитаемый план курса: `data/oge/course-plan.js`, `data/oge/delivery-manifest.json`

> **Главное правило курса:** тяжёлое — скачать и работать в настоящей программе, лёгкое — симулировать
> в сайте, но каждое практическое задание несколько раз делается на реальном инструменте.
> Всего по курсу — **32 живых прогона**, из них 11 на время: LibreOffice, Кумир, Python, файловый менеджер.
> Инструментов к установке ~424 МБ (LibreOffice 357,5 + Кумир 34,8 + Python 31,7 МБ); архив ФИПИ
> на 113,7 МБ целиком **не** качаем — берём из него только файлы заданий 13 и 14.

| Генератор каркасов модулей с проверками | `tools/build-oge-modules.js` |

Проверки генератора (падает, если не сходится):

```
node tools/build-oge-modules.js
→ Сгенерировано файлов модулей: 19
→ Сумма баллов по плану КИМ: 21 из 21
→ Норматив времени: часть 1 — 34 мин, часть 2 — 141 мин
→ Проверки согласованности пройдены.
```

Сумма баллов обязана равняться 21 — это защита от арифметических ошибок в плане
(именно она поймала ошибку с заданиями 13.1/13.2, где балл по невнимательности считался дважды).

**Почему 34 + 141 = 175, а не 150.** В официальном плане у каждого задания указано *примерное*
время, и его сумма больше продолжительности экзамена. Это нормально и означает простую вещь:
на экзамене приходится экономить, и план по времени — ориентир, а не бюджет. Симуляции
в модуле d18 нужны именно для того, чтобы ученик нашёл свой реальный темп.

## 2. Из чего состоит модуль

Каждый модуль закрывает одно задание ОГЭ (или группу) и лежит в своём файле —
ровно как модули базового курса.

```js
App.OGE_PLAN.push({
  id: "d15",              // короткий идентификатор
  exam: "14",             // какое задание ОГЭ закрывает
  name: "ОГЭ · Электронная таблица",
  ball: 3, hours: 10,     // вес в баллах и примерный объём работы
  engine: "table",        // движок практики сайта
  status: "каркас",       // каркас → черновик → готов
  goal: "…",              // что ученик умеет после модуля
  lessons: [              // план уроков
    { n: 1, kind: "lesson", title: "…", sub: "…", minutes: 67 }
  ],
  base: [121, 133, 137],  // уроки базового курса, которые уже закрывают тему
  gap: ["…", "…"],        // чего в базовом курсе нет — работа по второму курсу
  check: "…"              // критерий «модуль закрыт»
});
```

Типы уроков (`kind`):

| kind | Что это | Как выглядит на сайте |
|---|---|---|
| `lesson` | теория | текст с разметкой, как в базовом курсе |
| `practice` | практика с проверкой | движок (`sandbox`, `code`, `robot`, `table`, `graph`, `sql`) |
| `exam` | симуляция на время | таймер, набор заданий, оценка по критериям |

Поля `theory`, `tasks`, `practice` у уроков ОГЭ-курса — **точно те же**, что в базовом курсе.
Это сделано намеренно: движки практик, разметка теории и проверка ответов переиспользуются
без единой правки. Контракт описан в `docs/CONTRACT.md`.

## 4. Что нужно написать: приоритеты

Из плана видно, что **три четверти экзамена закрывает базовый курс**, а новое писать нужно
точечно. Самые важные доработки по убыванию пользы:

### Приоритет 1 — там, где теряют больше всего баллов

1. **Задание 14 (3 балла), модуль d15.** Нужны большие наборы данных (сотни строк, как в `.ods`
   из ФИПИ), блок условных вычислений (`СУММЕСЛИ`, `СЧЁТЕСЛИ`, `СРЗНАЧЕСЛИ`) и режим диаграмм
   с проверкой легенды в движке `table`. Это самое дорогое задание работы.
2. **Задание 15 (2 балла), модуль d16.** Нужен тренажёр универсальности: один алгоритм
   проверяется на 5 разных лабиринтах. Сейчас движок `robot` умеет один лабиринт.
3. **Задание 16 (2 балла), модуль d17.** Нужен формат экзамена: программа читает N, затем
   N строк, выводит одно число, и проверяется на тестах ФИПИ с автопроверкой.
4. **Задание 13 (2 балла), модули d13 и d14.** Это вообще новый тип работы: оформление
   документа и презентации по официальным критериям, в LibreOffice, в форматах `.odt` и `.odp`.

### Приоритет 2 — форматы и ловушки

5. Задания 11 и 12 (модули d11, d12): учебный архив файлов для поиска по содержимому
   и генератор дерева файлов для подсчёта по маске.
6. Задание 8 (модуль d8): круги Эйлера и формула включений-исключений — в базовом курсе темы нет.
7. Модуль d0: таймер на 150 минут и разбор ошибок по номерам заданий.

### Приоритет 3 — добить до автоматизма

8. Тренажёры по заданиям 1–7, 9, 10: генераторы однотипных задач с проверкой ответа.
9. Модуль d18: четыре полных варианта с таймером, автопроверкой части 1 и чек-листами
   для самопроверки части 2.

## 5. Как добавить ОГЭ-курс на сайт

Пока модули не подключены к `index.html` — специально: незачем показывать пустые модули ученику.
Когда в модуле появится содержимое, подключение — это одна строка на модуль:

```html
<!-- после data/lessons-bundle.js -->
<script src="data/oge/module-02-task-01-text-volume.js"></script>
```

Порядок: сначала `data/oge/oge-course.js` (каркас), затем файлы модулей. Уже подключён только каркас.

Дальше нужно решить три вещи (это отдельная задача, не текущая):

1. **Разделение курсов в интерфейсе.** Уроки ОГЭ-курса попадут в тот же список `App.LESSONS`
   с новыми id (300+). Нужен переключатель курса на странице `#/lessons` и в прогрессе,
   иначе 300 школьных уроков и модули ОГЭ смешаются в одну простыню.
2. **Отдельный счётчик прогресса.** `ST.summary()` считает всё подряд; для подготовки к ОГЭ
   нужен свой прогресс: сколько заданий закрыто, сколько баллов набирается в симуляции.
3. **Провожатый должен знать про ОГЭ.** Системный промпт в `scripts/ai/ai.js` уже обновлён:
   он знает официальные цифры (16 заданий, 21 балл, 150 минут) и что курсов два.

## 6. Рабочий процесс

```bash
# 1. правим план модулей (цели, уроки, доработки) — только в одном месте
#    data/oge/oge-course.js → App.oge.MODULES

# 2. пересобираем каркасы модулей (проверяет сходимость баллов)
node tools/build-oge-modules.js

# 3. обычные проверки сайта
node tools/smoke-test.js      # глобальные объекты и загрузка скриптов
node tools/render-test.js     # все страницы рисуются
node tools/check-content.js   # контент уроков
node tools/check-deploy.js    # готовность к статическому хостингу
```

Правило: **цели, часы, баллы и связи с базовым курсом правятся только в `oge-course.js`**,
файлы `module-*.js` — производные, их перезаписывает генератор. Ручные тексты уроков
добавляются в отдельные объекты (`LESSONS`), чтобы генератор их не затирал.

## 7. Границы: что этот курс не делает

- Не заменяет практику в настоящем LibreOffice и Кумире. Сайт тренирует мышление и формат,
  но задание 13 и часть задания 14 требуют живой программы на компьютере.
- Не даёт официальных баллов. Симуляции оцениваются по критериям ФИПИ, но это самопроверка.
- Не хранит варианты КИМов. Материалы ФИПИ используются как источник требований, а не как
  склад заданий: задания для тренировки генерируются и пишутся свои.
- Не обещает конкретный балл. План показывает путь, результат зависит от работы.
